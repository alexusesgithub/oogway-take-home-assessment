# Manual UI test plan

**Setup:** run `docker compose up --build`, open <http://localhost:8000> in a desktop browser, and keep `docker compose logs -f app` open in a terminal.

**Time:** about 20 minutes on a CPU-only laptop. Each case lists its acceptance criterion from [PRD §3](PRD.md#3-acceptance-criteria).

| ID | Area | Steps | Expected result | AC |
|---|---|---|---|---|
| T0 | First run | Start with a fresh volume (`docker compose down -v && docker compose up --build`). Open the app within 30 s. | Info banner "Building the knowledge base…" disappears within ~1 min. The sidebar footer shows "291 episodes · 17,427 passages" and the source commit. The header dot is green for Ollama, or amber "Preparing model…" while the model downloads. | AC15 |
| T1 | Grounded answer | Click the starter *How does Superhuman measure product-market fit?*, then press Enter. | Stage labels appear in order ("Searching transcripts", "N passages found" with guest chips, "Writing with qwen2.5:3b… Ns"), then the text streams. The final answer has numbered citation chips and a "N sources cited" badge, plus "Local · qwen2.5:3b" and the time. | AC2 |
| T2 | Evidence | Click a citation chip. | The Sources section expands, and the matching card is highlighted and scrolled into view. **Watch at mm:ss** opens YouTube at that second. **Transcript** opens the GitHub file at the pinned commit. | AC2 |
| T3 | Follow-up and isolation | Ask *What about for B2B companies?* Then click **New chat** and ask *What about for B2B companies?* again. | In the first chat, the answer stays on the PMF topic. In the new chat, the same text is treated without that context. Both chats appear in the sidebar, and reloading the page keeps both. | AC1, AC5 |
| T4 | Essay | In a chat with an answer, switch to **Essay** mode and send *Turn that into a Ship 30 essay*. | Stage labels go "Planning the essay outline → hook and intro → section n of 4 → takeaway", and the text streams into the chat. When done, the Artifact Viewer opens with a Markdown essay (`#` headline with a number, `##` sections, bullets, bold, takeaway, TL;DR). The chat shows "about N words, N sources cited, n/9 checklist items passed". Expanding **Ship 30 checklist** shows pass/fail per item. | AC6 |
| T5 | HTML artifact | Send *Make an HTML one-pager of the key ideas*. | The viewer shows a styled page. The **HTML** tab shows the source. **Download** saves a `.html` file, and **Full screen** and Esc work. The footer reads "Sandboxed preview: scripts, network requests, forms and external images are blocked". | AC7 |
| T5b | Artifact security | In browser devtools, inspect the iframe. | It has `sandbox=""` and its document carries a CSP meta `default-src 'none'`. `document.cookie` from the frame console throws or is empty, and no network requests come from the frame. | AC7 |
| T5c | Revision | Send *make it shorter*. | The route is "Artifact", a v2 appears, and the version selector lists v1 and v2. | AC8 |
| T6 | Not covered | Send *What's a good chocolate cake recipe?* | Within ~1 s, the reply says the transcripts don't cover it, with a blue info callout and suggestions. No "Writing with…" stage appears (the model isn't called). | AC4 |
| T7 | Provider toggle | Open the provider menu in the header. | Ollama (local) is ready with a green dot and labelled default. Claude (cloud) is disabled with "Not configured" and a hint, unless a key is set. With a key: select Claude, ask a question, and the answer's model chip reads "Cloud · claude-…". | AC9 |
| T8 | Model outage | Stop Ollama (quit the desktop app or `pkill ollama`), wait ~10 s, then ask a covered question. | A red dot and a banner explain the fix. The answer arrives as **evidence-only**: an amber callout with the error and hint, the top passages and citations. Restart Ollama and the next answer is normal. | AC10 |
| T9 | DB outage | `docker compose stop db`, then reload the app. Afterwards `docker compose start db`. | The app shows an error state rather than a blank page. `curl localhost:8000/health/ready` returns 503 `down`, and API calls return `database_unavailable`. After `start db`, the app recovers without a restart. | AC11 |
| T10 | Feedback and metrics | Click 👍 on an answer, then open `/api/metrics`. | The 👍 button stays highlighted. `helpful_rate`, `grounded_answer_rate` and latencies are populated. | — |
| T11 | Stop | Ask a question and click **Stop** while it streams. Wait 30 s and reopen the chat from the sidebar. | A toast explains that the server keeps working. The completed answer is in the chat after reopening. | — |
| T12 | Responsive | Resize to ~1000 px, then to 390 px (or use device mode). | At ~1000 px, the viewer overlays the chat. At 390 px, the sidebar is a drawer (hamburger), mode buttons are icons, there's no horizontal scroll, and the composer stays visible. | — |
| T13 | Keyboard and a11y | Navigate using only the keyboard: Tab through the controls, use `/` to focus the composer and Ctrl/Cmd+K for a new chat, then Esc. Optionally run Lighthouse > Accessibility. | Focus rings are visible everywhere, all controls are reachable, and Esc closes menus and the viewer. Lighthouse accessibility scores ≥ 90. | — |
| T14 | Dark mode | Switch the OS to dark mode. | All surfaces switch, text stays readable, and citation chips and badges remain distinct. | — |
| T15 | Deep link | Copy the URL (`#/c/<id>`) into a new tab. | The same chat opens with its messages and artifacts. | — |
